MoonEP 显式 Count 策略

四卡 · 每卡 S=1024，K=4，总 E=16 · 32 AIV · seed 42 · 2026-11-19

同一套候选代码提供两种调度。balanced 打开提前 Count 后，计算耗时从当前 PR 的 36.44 μs 降至 29.27 μs，配对下降 19.15%，与 DSL 相差 9.65%。热点输入开启后比当前 PR 慢约 26%，超过 5% 退化阈值，实验代码保留在工作区。

调用方式

plan = LatestDistributedPlan(group, E, S, K, workers=32, early_count=True)
outputs = plan(local_tpe, topk)

默认 early_count=False，先从 Greedy 结果判断是否需要 Count。True 在分布式、trusted、E=16、256<S×K≤4096、多核条件下，把 Count 分给 AIV 1 至 W−1，AIV 0 做 Greedy。其他规格回退。选择由调用方在构造时指定。接口未引入额外的跨卡协商。

验证范围

四种实现各预热三次、采样 20 次，六场景、四卡合计 2208 次 rank 调用，五个输出与独立 golden 及同轮对照逐元素相同。真实设备二进制、PID、设备及任务符号已核对。CPU 检查覆盖 500 种参数及分配组合。

另外在单卡、严格校验、E=12、单 AIV、双卡尾块五组规格上分别运行两种策略，各九轮，共 234 个 rank-round，含重复使用、stream 和 shape 保护，十组全部通过。
