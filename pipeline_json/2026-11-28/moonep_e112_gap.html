源码如何形成差距

  1. Assign。 PyPTO E112 用 32 AIV，每核 16 线程，一共处理 512 个 chunk。每线程先扫 112 位专家，再依次处理 256 个路由项。E16 小网络已有的 SIMD 投影在 E112 未启用。DSL 一块处理 1,024 项，先求每位专家的块内目标 VID，再用 64 个 int32 lane 做 SIMD gather，仅压缩并逐项处理实际跨段的专家路由。
  2. Prefix。 PyPTO 按 128 个专家分组，E112 只有一个 AIV 写专家前缀。每个标为可变的专家顺扫 512 个 chunk。balanced 是 3 行、1,536 项，skewed 是 22 行、11,264 项。DSL 将专家行分给多个 block，每行覆盖 128 个 chunk。
  3. Count。 PyPTO 用 31 个 AIV、每核 64 线程做共享 UB 原子直方图，每个 256 项 chunk 经清零、计数、写回三次线程同步。DSL 的 1,024 项 chunk 使用向量直方图。skewed 的更新集中在较少的桶，原子争用的额外耗时尚未经计数器单独证实。
  4. Exchange。 两组每卡都向其余三卡发送 3 × 448 B 的有效统计，另有到达标记。PyPTO 先做 Window 入口屏障，AIV 0 遍历 peer；DSL 将各 peer 的发送分给不同 block。通信等待会叠加各 rank 到达时间差。相同字节数不能证明两者通信时间相等。

优化的验证顺序

skewed 先为只有一个正配额目的地的专家发布固定 VID，包含迁至远端副本槽的专家。按本次输入，可将 356,394 个路由项移出逐项状态分支。真正拆分的专家保留原有 source rank 偏好与段顺序。balanced 无整迁专家可受益，应直接对 E112 验证块级 VID 表与 SIMD gather。每次只改一项，复核四卡五输出与配对墙钟。

Greedy 的并行度也不同

E112 没有命中 PyPTO 针对小规格 E16 的 scalar 特化。AIV 0 以一个 SIMT 线程执行 _stage_zero_ub[1]，选迁移专家时顺扫源 rank 的 28 个候选，再用 64 线程发布结果。DSL 的 _greedy_all 对候选做 warp 归约，同值时按最小下标破平局。skewed 的初始需求全在一个 home，整迁专家更多，会放大决策工作量。前段同时包含 Exchange、Count 和 Greedy，截断计时无法进一步把这三者单独归因。
