安装与通信依赖

独立安装了 x86_64 Toolkit、950-ops 和 NNAL，三个 runfile 均通过官方 SHA-256。Toolkit 自带的 DSL 0.8.4 含 CPython 3.12 扩展及绑定源码。沿用环境 0 的 Python 3.10.20，以独立的 pybind11 2.13.6 构建，已实际导入 _comm_native。进程加载的 libaiv_comm、libascendcl、libhccl 与 libhcomm 均来自本次 Weekly。原环境的 PyPI cp310 同版本包缺少该扩展。

同机对照使用的编译配置

首次使用环境 0 原 PyPTO 框架 eb60d7b 和新 CANN，DSL 六组、24 份 rank 输出均通过 CPU golden。PyPTO 的毕昇编译在新 CANN 头文件中遇到 ReadGmByPassDCache 等弃用告警，原有 -Werror 将其提升为错误。直接切换到 Weekly 随附的 PyPTO 时，离线解析器又无法识别 PR 使用的 pld.make_dtensor。

复验保留 PR !1118 的算子源码和原 PyPTO 框架，在框架独立副本中仅为 DAV_3510 增加 -Wno-error=deprecated-declarations，保留其他告警检查和优化参数。E=16 和 E=112 两个融合 kernel 先后通过离线编译。报告按实际完成的 qrun 轮次标注结果；两侧在同一次复验中各自启动四卡进程。

输入与判定

压缩包生成器，seed 42。balanced 从全部专家无放回选 K 个，skewed 从前 max(K,E/4) 个专家抽取，extreme 固定选择 0 至 K−1。每个 rank 使用本地 topk 计算 tpe。输出记录原始形状，并按相同的路由顺序核对整数内容。四卡大规格按每卡 28 个专家得到 E=112；包内八卡推荐规格 E=224 单独验收。
