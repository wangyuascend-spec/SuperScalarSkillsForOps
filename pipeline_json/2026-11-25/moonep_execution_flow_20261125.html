AIV 0 · 交换与 Greedy

向其他三卡交付本卡的一行计数，等三份远端 ready，形成完整 dem[4,E]。
Greedy 根据全局需求确定各专家的服务 rank、分配量及路由模式，发布供其他 AIV 使用的表。

AIV 1–31 · 本卡 Count

满足提前 Count 条件时，31 个 AIV 分摊本地 topk 的分块直方图，只读本卡输入。这段工作可覆盖 AIV 0 的交换和 Greedy。
未开启或条件不满足时跳过。后续只有 mode 1 需要逐块 Count。
① AIV 全核同步 · 等 Greedy 发布完成，也等已启动的提前 Count 完成

mode 0 · 全部本地归属

没有远端服务或拆分。各核从专家编号直接算出 home slot，写出虚拟路由。

全核同步共 1 次

mode 1 · 存在拆分

至少一个专家由多个 rank 服务。未提前 Count 时，全核做 Count，随后加一次同步。各核做 Tables / Prefix，再同步，Assign 按分块前缀逐项选副本。

提前 Count 共 2 次；延后共 3 次

mode 2 · 固定远端

有专家整体移到远端，每个专家仍有唯一服务位置。生成稳定映射，按固定 slot 写出虚拟路由。

全核同步共 1 次

同步次数只计 sync_all(AIV_ONLY)。入口 Window barrier 和各核内部的管线事件、缓存维护另计。严格校验路径有独立的输入检查与同步结构。

提前 Count 与最终路由模式在何时决定？

交换前即可使用的信息

设 N=S×K。提前 Count 要求 trusted 路径、E=16、256<N≤4096 且有多个 AIV。False 始终延后；True 在规格满足时提前；auto 还会检查本卡 tpe。若任一专家满足 tpe[e]×E > 2×N（超过均值两倍），本卡关闭提前 Count。其他 AIV 可在 AIV 0 等待时做这个判断。

交换后才能确定的信息

Greedy 从完整 dem 算出 mode 0/1/2。balanced、skewed、extreme 是测试输入的生成方式，kernel 实际读取计数。提前 Count 预测值与 Greedy 结果是两个独立决定；即使预测提前，最后走 mode 0/2 时也可能已经做过额外工作。

AIV 0 的交换路径

UB_MEM · 通过远端映射写入

本卡 GM 的 tpe → 本地 UB tile
向四个 rank 的映射 GM 写入本卡行，含自身
等待写完成并做 DDR 屏障，对另外三卡原子递增 ready[本卡]
轮询另外三卡的 ready[source] 到本轮 epoch
将接收矩阵整体经 UB 搬到规划所用 dem

URMA · GM 行直接投递

选择另外三卡的 URMA channel
逐 peer：从本卡 GM 的 tpe 发 WriteNotify 至对端 dem 的本卡行，同时通知该来源的 ready
每次投递后调用 Drain，再处理下一 peer
轮询另外三卡的 ready[source] 到本轮 epoch
维护缓存、补写自己的 dem 行，再维护缓存；远端行已经就位
