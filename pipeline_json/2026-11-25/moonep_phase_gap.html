小网络 balanced

四卡，每卡 S=1024、K=4，总 E=16，32 AIV。seed 42 在全部专家中选择路由。每轮依次交替正序和逆序调用四个实现，预热 3 轮、测量 20 轮。每次调用均逐元素核对五项输出，并检查独立 CPU 参考。profiler 的 PID、设备、加载的二进制摘要、kernel 符号和调用顺序均已核对。默认与提前 Count 使用相同旧 UB 实现；自适应使用本卡信息选择调度。DSL 参考选择源码自带的标量 Count 分支。

自适应计算相对 DSL 的四卡中位差为 2.67 μs，端到端差为 51.81 μs。rank 0 在三个实现里都最慢。11 月 24 日同方法测得自适应和 DSL 的 full 中位数为 54.75 和 42.99 μs，compute 为 28.38 和 26.14 μs。跨批变化主要出现在需要各卡同步的 full 路径。该现象与到达时差或等待开销相符；本次小网络采集没有单独记录发送、等待或链路计数，无法确认具体原因。

未插桩时，两版逐轮最慢卡的中位耗时分别为 1800.27 和 2061.19 μs，URMA 增加 260.92 μs（14.49%）。在这一慢卡上，发送至本地完成（URMA 包括 WriteNotify 和 Drain）增加约 262.63 μs，ready 等待仅增加约 0.10 μs。该段是本次关键路径上观测到的最大差异，当前粒度无法进一步拆开投递请求与 Drain 等待。该 rank 上 UB 和 URMA 的整核插桩扰动分别约 +0.14% 与 +1.63%；URMA 四卡中位数的扰动约 +15.08%。

阶段数据汇总四卡各 20 轮。在同一 AIV 上读取设备计数器后求差。ready 等待同时受对端到达时刻影响；各阶段独立取中位数，数值不具有可加性。其他核与通信核存在并行区间。实际端到端结论采用未插桩的 msprof Task Duration。

大网络同框架、未插桩的 URMA 相对 UB_MEM 耗时变化为 +36.57%（+101.86 μs）。该组未重新采集 DSL 计时。两种网络使用不同输入规格及路由分布，仅在各自的配对组内比较。

复核依据

小网络对应环境 0 的 moon_plan/logs/ub-small-balanced-1125，四个进程各运行 92 次调用，按设备及已加载符号与 msprof 匹配。大网络对应 moon_plan/urma-phase-112-c1，URMA 算子基线 5307fd2，PyPTO !7776 基线 3423d7e。大网络采用相同框架重建 UB 通信对照，每个版本独立启动四个进程；先验证独立 CPU 参考和预先保存的四卡 DSL 输出，再做设备计时。3510 的 get_sys_cnt 为 1000 MHz，每 tick 为 1 ns。原始卡级测量和阶段统计见同目录 JSON。
