当前可验证的差异

PyPTO 为先判断 mode0/2 快路径，把 Count 放在第一次阶段同步之后。balanced 走 mode1，因此它先完成 Greedy，再启动 Count，共经过三次阶段 SYNCALL。DSL 在第一个阶段同时安排 Count 与 Greedy，后续仅两次 global_sync_all。这里可能同时包含额外同步和缺少计算重叠，但现有数据还不能为各段分配微秒占比。

Count 的512B写入所有权将16个chunk分成两组，每组8行，只由两个AIV处理。Prefix 的专家分组为128，E16只有AIV0上的16个lane有效。Tables在AIV0内4线程分rank。Assign最新T1已经覆盖16个AIV，旧T32的单核瓶颈已修正。

Publish 原阶段与消融动机

优化前 _publish_greedy 在 worker0、trusted 路径中由64个lane对同一个GM flag执行 atomic_add(flag[0],0)，每个lane随后按返回值分支。该阶段约19.2k cycles，与源码的重复一致性读取共同构成实验动机。原子操作本身的比例仍不能从串行化阶段推算。一次coherent读取后UB广播方案已通过完整调用正式对照与mode0/1/2相关回归。

如何解释这些周期

每核独占512B trace，helper之后额外加入V→S完成事件和DDR DSB，使阶段执行串行化并改变原有重叠。这里保留raw cycles，不转换微秒，不跨核相减，也不把各格相加生成生产kernel占比。skewed mode2的fixed Assign仅约498 cycles，与balanced的普通Assign具有不同工作量。

后续结构实验

当前 trusted mode1 阶段探针已经完成。Publish 单一机制实验已完成正式确认，后续可进一步比较“Count 与 Greedy并行”的完整调用候选，同时保留 skewed/extreme 快路径回归控制。该候选可能使 mode0/2 多执行无用 Count，尚未证实收益。

已确认的输入特点

balanced 每 token 从全部16专家无放回选择4个；seed42 需求统计已确认触发部分专家拆分，状态为 mode1。skewed 从 max(K,E/4)=4 个专家选择4个，extreme 固定专家0–3，因此两者 tpe 相同、走 mode2。默认 trusted 的 mode2 会绕过普通 Count/Prefix/Assign，不能用该快路径耗时解释 balanced。
